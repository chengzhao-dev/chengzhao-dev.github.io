为什么是“做完整”

“完整”不是“完美”。一个完整的项目通常只需要几样东西：一条能复现的运行路径，一组能说明问题的测试，一份写到别人能上手的说明，以及一个不会在下次修改时立刻崩掉的结构。它们都不难，但需要有人愿意停下来做完。

我把这个标准用在自己的笔记上。每个 C++ 例子尽量能编译；每篇建站文章尽量说明版本和前置条件；每次发布尽量走同一条流水线。做不到的时候，就在文章里写清楚哪里还没做到。

这个网站怎么来的

网站用 Quarto 构建，主题是在 Bootstrap 之上写的一层 SCSS 和 CSS，没有前端框架，也没有后端。字体自托管，页面由 GitHub Actions 发布到 GitHub Pages。

它也是 dsh-quarto-website 这个插件的第一个使用者：主题、检查清单和发布流程先在这里跑通，再收回插件里。下次做类似的站点时，不需要从空白页开始。

几条工作原则

01
先跑通，再抽象

能运行的最小版本，比一张完美的架构图更有用。

02
写下来，才算学会

笔记不是摘抄，是一次重新组织，让别人也能照着做。

03
把发布交给机器

构建、检查和部署应该重复、可预期，不靠记忆。
